# MAHARA

Интернет-магазин на HTML/CSS/JavaScript с серверной панелью управления на PHP 8.2+ и SQLite. Подготовлен под виртуальный хостинг REG.RU Host-0. Node.js нужен только для локальных проверок и упаковки, на хостинге он не требуется.

## Локальный запуск

Требуются PHP 8.2+, `pdo_sqlite`, HTTPS-запросы через cURL/OpenSSL и актуальные доверенные корневые сертификаты. Для QR-кода нужен DOM/XML. PHP для этого рабочего места расположен в `.runtime/php` и не попадает в поставку.

Запустите `start.bat` (Windows) или `./start.sh` (Linux с PHP в PATH), затем откройте http://localhost:8000/.

Админка: http://localhost:8000/admin/login. Ссылка скрыта из публичного меню. Прямой переход к `/admin.html` без сессии отправляет на вход; API также проверяет доступ на сервере.

Локальный доступ владельца записан в `.local/preview-access.txt`. Этот файл, SQLite и локальные библиотеки исключены из Git и поставки. Пароля по умолчанию нет.

Создать своего администратора в Windows:

```powershell
$env:APP_ENV = 'development'
.\.runtime\php\php.exe tools/admin.php create
```

В Linux: `APP_ENV=development php tools/admin.php create`. Для смены пароля существующего администратора добавьте `--replace`: старые сессии будут отозваны. Пароль вводится скрыто. Переменные `MAHARA_ADMIN_USERNAME` и `MAHARA_ADMIN_PASSWORD` предназначены для автоматизированной настройки, не записывайте их в репозиторий.

## Управление содержимым

- Редактирование первого экрана, кампании, истории бренда и блока новостей со ссылками на соцсети.
- Редактирование товаров и добавление новых: название, категория, цвет, цена, размеры, описание, состав, уход, изготовитель, замеры и две фотографии. Фактические сведения заполняет магазин; пустые значения не выдумываются.
- Загрузка JPEG, PNG и WebP на сервер, предпросмотр и публикация кнопкой «Сохранить изменения».
- Серверное хранение в SQLite; фотографии находятся в приватном каталоге данных и выдаются через приложение.
- Автоматическое появление товаров в каталоге, отдельных страницах и sitemap. HTML и метаданные содержат опубликованную версию даже без JavaScript.
- Защита от одновременной перезаписи: устаревшая версия получает 409, черновик сохраняется на экране.

Сессии имеют ограниченный срок, HttpOnly/SameSite cookie и Secure в production. Пароли хранятся как bcrypt-хеши; административные запросы проверяют сессию, Origin и CSRF-токен. Есть ограничения попыток входа и размера файлов.

## Склад

Раздел «Склад» доступен из админки или по `/inventory.html` после входа. Здесь можно вести остатки отдельно по размерам, оформлять приход, списание и инвентаризацию, искать товары, фильтровать наличие и выгружать остатки в CSV. Списание и пересчёт требуют причины; журнал сохраняет количество до/после, время и администратора. Удаление с витрины сохраняет учтённые остатки и историю в архиве склада.

Изначально остатки не заданы. Внесите фактические количества через «Пересчитать» или оформите поступление. При создании заказа товар резервируется, а подтверждённая банком оплата один раз списывает его со склада. Ручное списание и пересчёт не могут уменьшить остаток ниже резерва. Возврат денег не возвращает одежду на склад автоматически.

Витрина получает доступность размеров через `/api/catalog/availability`: неподтверждённые и отсутствующие остатки недоступны для покупки, действующие резервы учитываются. Эта ручка не создаёт остатки и не освобождает резервы. Корзина синхронизируется между вкладками, количество ограничено 20 единицами одного размера. Избранное сохраняется в браузере и доступно фильтром каталога.

## Оформление, СБП и СДЭК

Корзина ведёт на `/checkout.html`. Цены и доступные количества проверяет сервер. Оплата проходит через СБП Т-Кассы; возврат покупателя на сайт не подтверждает поступление денег. Заказы доступны владельцу в `/orders.html`: контакты, товары, пункт выдачи, статус оплаты, обработка отправления и полный возврат.

Доставка оплачивается покупателем СДЭК отдельно. Оформление позволяет выбрать город и ПВЗ и получить расчёт по договору магазина до оплаты одежды. Расчёт не создаёт накладную; отправление оформляет магазин. Вес и габариты задаются для каждой упакованной вещи по категории; при расчёте нескольких вещей каждая считается отдельным местом. Для другой схемы упаковки требуется изменить расчёт пакетов.

Данные для локальной настройки:

- `.local/tbank-secrets.php`: `terminal_key` и `password` терминала интернет-эквайринга.
- `.local/cdek-secrets.php`: `account` и `password` интеграции СДЭК. Карта и ключ Яндекс Карт для выбора ПВЗ списком не нужны.
- `server/config.local.php`: настройки из примера — домен, подключённая касса, фактические налогообложение/НДС, условия продажи, политика персональных данных, город отправления, тарифы и параметры упаковки.

Секреты исключены из Git и поставки; на хостинге они находятся в приватной папке данных. Оплата по умолчанию выключена и не включается без обязательных настроек. Отчёт о готовности без показа паролей и без обращений к банку: `node tools/php.cjs tools/commerce.php status`.

## Документы и уведомления

Страницы `/terms.html`, `/privacy.html`, `/delivery.html`, `/returns.html`, `/contacts.html` формируются сервером из блока `merchant` приватной конфигурации. Пока реквизиты, фактические условия и обработка данных не подтверждены владельцем (`published=true` + версия), страницы исключены из индексации. По решению владельца статус черновика больше не блокирует оплату; он не меняет статус публикации страниц. Для оформления по-прежнему нужны корректные ссылки на условия и политику и согласие покупателя; заказ сохраняет принятые ссылки и фактическую версию, а незаданная версия встроенных документов остаётся пустой. Их наличие не заменяет проверку владельцем реальных процессов магазина.

На оформлении отдельно принимаются условия заказа и показывается политика обработки данных. Принятие условий не оформляется как согласие на рекламу. Формы подписки на рассылку нет: новости доступны по существующим ссылкам на соцсети. Аналитические и рекламные трекеры не добавлены.

Почтовая очередь готова для создания/оплаты/отправки/завершения заказа и подтверждённого возврата. Настройте `mail` и приватный `mail-secrets.php`, затем запускайте `php tools/notifications.php send` из cron. При выключенной почте письма не создаются и не отправляются. Неудачная отправка не меняет финансовый статус. Почтовая доставка может повториться при неопределённом сетевом результате; идентификатор сообщения остаётся стабильным.

После подключения почты на оформлении доступно «Найти оформленный заказ» по его номеру и почте. Ссылка одноразовая, действует 24 часа; её секрет передаётся во фрагменте URL и сразу убирается из адресной строки. Восстановление на другом устройстве не очищает локальную корзину. Без почты доступ остаётся в исходной вкладке; ссылка `?order=…` сама по себе доступа не даёт.

## Публикация

Порядок настройки REG.RU описан в [DEPLOYMENT.md](DEPLOYMENT.md). Подготовить чистый каталог:

```sh
node tools/package-release.cjs
```

Поставка создаётся в `.local/releases/`. Она не содержит базы данных, паролей, локального PHP или Git. В production HTML-шаблоны помещаются в `server/templates/*.html.php`, чтобы nginx не выдавал защищённую админку или старые страницы как статические HTML.

`PHP_BINARY` позволяет указать другой путь к PHP для серверных тестов. Тесты используют отдельные временные базы и не меняют рабочий каталог товаров.

## Что ещё нужно для продаж

Код оформления, СБП и расчёта СДЭК подготовлен; приём реальных денег требует настройки терминала, фискализации и проверки на хостинге. Локальные тесты используют имитацию ответов провайдеров и не подтверждают подключение рабочего терминала. Накладные СДЭК магазин создаёт отдельно; карта пока отсутствует, выбор ПВЗ работает списком после подключения API. Почтовый код готов, но требует настоящей почты и cron. Контакты, реквизиты, условия, цены, сведения о товарах, реальные остатки и параметры упаковки нужно подтвердить перед коммерческим запуском.

В Init передаётся чек полной предоплаты в подключённый сервис кассы. Принятие запроса банком не подтверждает фискализацию. При передаче товара нужен чек зачёта предоплаты, а для маркируемой одежды — соответствующие данные маркировки; автоматический закрывающий чек пока не реализован. Магазин должен настроить этот этап в своей кассе до продаж.

Проверки склада: `php tests/inventory.php` и `node tests/inventory-browser.cjs`. Для Windows можно использовать `.runtime/php/php.exe`; переменная `PHP_BINARY` задаёт PHP для браузерной проверки. Тесты создают отдельную временную базу и не меняют рабочие остатки.
